# سامانهٔ تمدید بیمهٔ تکمیلی

نسخه اولیه گردش کار تمدید سالانه بیمه تکمیلی. کارمند برای یک دوره باز یک درخواست می‌سازد، افراد تحت پوشش را انتخاب یا اصلاح می‌کند و برای منابع انسانی می‌فرستد. کارشناس منابع انسانی همان درخواست را تأیید نهایی می‌کند یا با ذکر دلیل برمی‌گرداند.

محصول بیمه‌ای کامل نیست: محاسبه حق بیمه، مدارک، پیامک و سامانه بیرونی در محدوده این کار نیست.

## پیش‌نیاز

- Python 3.12، 3.13 یا 3.14
- Django 5.2 روی Python 3.15 نصب نمی‌شود. اگر دستور `python3` روی دستگاه شما 3.15 است، محیط مجازی را با `python3.14` بسازید.

هیچ سرویس خارجی لازم نیست. پایگاه داده فایل SQLite کنار پروژه است.

## نصب و اجرا

```bash
python3.14 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

سپس در مرورگر باز کنید: <http://127.0.0.1:8000/>

اجرای تست‌ها:

```bash
python manage.py test renewals
```

Admin جنگو فقط برای دیدن یا ساختن داده آزمایشی است و جایگزین پنل‌ها نیست. در صورت نیاز:

```bash
python manage.py createsuperuser
```

و بعد <http://127.0.0.1:8000/admin/>.

`seed_demo` را دوباره اجرا کنید گذرواژه‌های آزمایشی را بازنشانی می‌کند. اگر تاریخچه دوره قبل وجود داشته باشد، درخواست تکراری نمی‌سازد. برای شروع از صفر، `db.sqlite3` را پاک کنید و `migrate` و `seed_demo` را دوباره بزنید.

## کاربران و دوره‌های آزمایشی

| نقش | نام کاربری | گذرواژه |
|---|---|---|
| کارمند | `sara.karimi` | `Renew-Sara-1405` |
| کارمند دوم | `reza.ahmadi` | `Renew-Reza-1405` |
| منابع انسانی | `hr.nazari` | `Renew-HR-1405` |

- دوره **تمدید ۱۴۰۴** بسته است و برای هر دو کارمند یک درخواست تأییدشده دارد.
- دوره **تمدید ۱۴۰۵** باز است و هنوز درخواستی ندارد.
- افراد تحت پوشش سارا در شروع دوره جدید: خودش و فرزندش آرمین. همسر از قبل در پوشش سال قبل نیست.
- نمونه معتبر برای افزودن همسر: مریم کریمی، کد ملی `0087654326`، تاریخ تولد `1369/12/24`.

روی صفحه ورود، وقتی `DEBUG` روشن است، همین حساب‌ها نشان داده می‌شوند. با `DJANGO_DEBUG=0` آن راهنما مخفی می‌شود.

## نمایش پنج سناریوی پذیرش

1. با سارا وارد شوید، درخواست ۱۴۰۵ را بسازید، همسر را اضافه کنید و ارسال کنید. با حساب منابع انسانی همان درخواست را تأیید کنید.
2. برای رضا درخواست بسازید و ارسال کنید. منابع انسانی آن را با دلیل برگرداند. رضا اصلاح کند و دوباره بفرستد.
3. با سارا، شناسه درخواست رضا را در نشانی صفحه عوض کنید. صفحه «پیدا نشد» می‌آید و داده‌ای عوض نمی‌شود. نشانی `/hr/` هم برای کارمند بسته است.
4. سارا پس از ساخت درخواست ۱۴۰۵، یک بار دیگر «ساخت پیش‌نویس» را بزند. سامانه درخواست دوم نمی‌سازد.
5. در درخواست ۱۴۰۵ نام آرمین را عوض کنید. بعد درخواست تأییدشده ۱۴۰۴ همان کارمند را باز کنید. آنجا هنوز نام قبلی آرمین است.

## فرض‌ها و تصمیم‌های طراحی

- هر درخواست، افراد انتخاب‌شده را در `CoverageLine` کپی می‌کند. ویرایش در دوره جدید همان خط و رکورد جاری فرد را به‌روز می‌کند و خطِ درخواست‌های قبلی را دست نمی‌زند. حذف از دوره جدید هم فقط همان خط را برمی‌دارد.
- نسبت «والدین» در مدل هست، چون قوانین کسب‌وکار والدین را نام برده‌اند. جدول حداقل داده‌ها فقط خود، همسر و فرزند را نوشته بود.
- هر کارمند دقیقاً یک فرد با نسبت «خود» دارد. این خط از درخواست قابل حذف نیست. نام این خط با نام کارمند همگام می‌شود.
- برای هر کارمند در هر دوره فقط یک درخواست مجاز است. این قاعده هم در سرویس بررسی می‌شود و هم قید یکتای پایگاه است.
- فقط یک دوره می‌تواند باز باشد. درخواست تازه فقط برای همان دوره ساخته می‌شود.
- کارشناس منابع انسانی عضو گروه جنگو به نام `hr` است و پروفایل کارمند ندارد. افراد تحت تکفل حساب کاربری ندارند.
- تأیید و بازگشت فقط از وضعیت «ارسال‌شده» ممکن است. ویرایش فقط در «پیش‌نویس» و «نیازمند اصلاح» ممکن است. درخواست تأییدشده بسته است.
- تاریخچه، ارسال و ارسال مجدد و بازگشت و تأیید را با زمان، اقدام‌کننده و توضیح نگه می‌دارد. ساخت پیش‌نویس رویداد تاریخچه نیست؛ زمان ساخت روی خود درخواست است.
- اگر کارمند شناسه درخواست دیگری را در نشانی عوض کند، پاسخ ۴۰۴ است تا وجود آن درخواست هم لو نرود.
- کد ملی رشته ۱۰ رقمی است و رقم کنترل کد ملی ایران بررسی می‌شود. احراز قانونی تحت تکفل انجام نمی‌شود.

## محدودیت‌ها
